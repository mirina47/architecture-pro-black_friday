## Задание 7. Проектирование схем коллекций для шардирования данных

### 1. Схемы коллекций

### Коллекция orders
```
_id: Integer
client_id: Integer
created_at: Timestamp
items: Array[
    name: String
    price: Decimal128
]
status: String
total_amount: Decimal128
geozone: GeoJSON
```

### Коллекция products
```
_id: Integer
title: String
category: String
price: Decimal128
stock: {
    zone_id: Integer
    quantity: Decimal128
    updated_at: Timestamp
}
attr: {
   color: String

```

### Коллекция carts
```
_id: Integer
user_id: Integer 
session_id: Integer
client_id: Integer // user_id или session_id

    product_id: Integer

status: String enum ["active", "ordered", "abandoned"]
created_at: Timestamp
updated_at: Timestamp
expires_at: Timestamp
```

### 2. Стратегии шардирования

### Коллекция orders
**Шард-ключ**: ```{ client_id: 1, _id: 1 }```

**Стратегия**: Диапазонное шардирование

**Обоснование**:
- Ключ client_id обеспечивает быструю работу таких запросов, как поиск истории заказов конкретного клиента. Добавление _id помогает равномерно распределить заказы очень активных клиентов.
- Диапазонное шардирование подходит, так как заказы относятся к последовательным данным. Также в плюсах легкая реализуемость и быстрый поиск информации по сравнению с хэшированием.

**Пример команды**: 
```
sh.shardCollection("db.orders", { client_id: 1, _id: 1 })
```

### Коллекция products
**Шард-ключ**: ```{ "_id" : "hashed" }```

**Стратегия**: Хэшированное шардирование

**Обоснование**:
- Ключ _id уникален, поэтому может обеспечить хорошее распределение данных
- Хэшированное шардирование подходит, так как товары в магазине крайне важно распределять равномерно. Также в плюсах высокая производительность и отсутствие единой точки отказа.

**Пример команды**: 
```
sh.shardCollection("db.products", { "_id" : "hashed" })
```

### Коллекция carts
**Шард-ключ**: ```{ "client_id" : "hashed" }```

**Стратегия**: Хэшированное шардирование

**Обоснование**:
- Ключ client_id обеспечивает быстрый доступ для операций добавления/удаления товаров в корзине.
- Хэшированное шардирование подходит, так как нагрузка распределена равномерно, что крайне важно в период акций. Также в плюсах высокая производительность и отсутствие единой точки отказа.

**Пример команды**: 
```
sh.shardCollection("db.carts", { "client_id" : "hashed" })
```

## Задание 8. Выявление и устранение «горячих» шардов

### 1. Набор метрик
1. Метрики нагрузки
- opcounters — количество операций в секунду. 
- latency — время выполнения команд.
- connections — активные соединения.

2. Метрики ресурсов
- CPU — загрузка процессора.
- RAM — использование памяти.
- queue — очереди операций.
- cache — эффективность кэша.

3. Метрики распределения данных
- chunk_size и chunk_count — распределение чанков.
- jumbo_chunks — неделимые блоки.

4. Сетевые метрики
- network — сетевая активность.

### 2. Механизмы автоматического перераспределения данных
1. Переход на хэшированное шардирование

Если текущая стратегия приводит к перегрузке, рекомендуется перейти на хэшированное распределение. Обоснование было указано в задании 7.

```
sh.shardCollection("db.products", { "_id" : "hashed" })
```

2. Оптимизация ключа шардирования  

Если используется диапазонное шардирование и текущий ключ { category: 1 } создает горячий шард, необходимо превратить ключ в составной { category: 1, _id: 1 }. Таким образом нагрузка будет распределена более равномерно.

```
sh.refineCollectionShardKey("db.products", { category: 1, _id: 1 });
```

3. Балансировщик нагрузки

Встроенный балансировщик MongoDB автоматически перемещает чанки с перегруженных шардов на менее нагруженные. Его можно полностью включать и отключать, также можно настроить время работы по расписанию.

```
sh.getBalancerState();
sh.startBalancer();

db.settings.update(
    { _id: "balancer" },
    { $set: { activeWindow : { start : "01:00", stop : "05:00" } } },
    { upsert: true }
);
```

4. Геошардинг

Геошардинг можно комбинировать с актуальной стратегией шардирования. Так данные распределятся более равномерно. 
```
// Создание зон для разных шардов
sh.addShardToZone("shard1", "USA")
sh.addShardToZone("shard2", "EUROPE") 
sh.addShardToZone("shard3", "ASIA")

// Привязываем диапазон категории к зоне:
sh.updateZoneKeyRange(
    "shop.products",
    { category: "Electronics", _id: MinKey },
    { category: "Electronics", _id: MaxKey },
    "USA"
);
```
